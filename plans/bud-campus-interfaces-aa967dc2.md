# خطة واجهات BUD Digital Campus

## الهدف والتسليم
تصميم وتنفيذ 18 شاشة إنكليزية احترافية لعرض مشروع التكامل الجامعي على رئاسة The British University in Damascus، وتسليمها كمعرض React عالي الدقة جاهز للتصوير والاستخدام في المونتاج، مع حركة سينمائية ووضع Story Mode يشغّل الحالات الثماني تلقائيًا ليُسجَّل كفيديو شاشة مباشرة. لا يشمل العمل إنتاج الفيديو أو النص الصوتي، ولا بناء نظام إنتاجي، ولا ملف Figma بطبقات قابلة للتحرير. الصور تُصدَّر فقط إذا توفرت أداة التقاط؛ وإلا يُسلَّم المعرض مع مقاسات واضحة وروابط مباشرة لكل لقطة.

## القرارات المعتمدة من المستخدم
- الحركة: حركة كاملة مع Story Mode تلقائي.
- الصور: صور مختارة بعناية من Unsplash، بمعالجة لونية كحلية موحدة.
- الموبايل: زر تبديل بين إطار هاتف واقعي وشاشة نظيفة 390×844.
- لوحة الرئاسة: غرفة قيادة كحلية داكنة بالكامل.

## حقائق البيئة
- src/App.tsx فارغ حاليًا؛ React 19 وVite 8 وTailwind CSS v4؛ CSS العام في src/index.css (يحوي `@import 'tailwindcss';` فقط).
- لا توجد مكتبات حركة أو أيقونات؛ تُضاف `motion` و`lucide-react` عبر pnpm.
- خادم المعاينة يعمل تلقائيًا ولا يُشغَّل خادم إضافي.
- مصدر المتطلبات: BUD-Graduation-Project-Proposal-v2.docx (المرفق f684bc38-…)، والشعار من المرفق image.png (9881e4bd-…) يُجلب عبر `figma attachments get` ويُنسخ إلى `src/assets/bud-logo.png`. يُستخدم كما هو على مساحة بيضاء دون إعادة رسم أو قص أو تشويه.

## الحركة وStory Mode
- مكتبة `motion` (`motion/react`). مدد قياسية: دخول الشاشة 450–600ms بانزلاق 16px وتلاشٍ، تتابع البطاقات بفاصل 60ms، رسم خطوط الرسوم البيانية عبر `pathLength`، عدّ الأرقام 900ms، انتقالات الحالات (تحول زر إلى Published، ظهور إشعار من أعلى الهاتف) بنوابض هادئة. لا ارتداد مبالغ فيه.
- `prefers-reduced-motion`: تعطيل الانزلاق والعدّ والإبقاء على تلاشٍ قصير.
- **Story Mode** (`src/story/storyScript.ts` + `StoryPlayer`): سلسلة خطوات ثابتة، كل خطوة = {screen، action اختياري، highlight اختياري لعنصر عبر `data-story` id، caption قصير إنكليزي، duration}. التسلسل:
  1. W01 مقدمة (5s) → 2. M01 (4s) → 3. M02 اختيار A وإظهار التعارض (4s) → 4. اختيار B والتأكيد (4s) → 5. M03 (3s) → 6. M06 عدّ الفاتورة (4s) → 7. W07 (3s) → 8. W05 فتح التأكيد ثم النشر (5s) → 9. M01 إشعار النتيجة (3s) → 10. M07 (3s) → 11. M08 طلب ثم Ready ثم المعاينة (6s) → 12. W02 نشر القرار (4s) → 13. M01 إشعار القرار (3s) → 14. W06 تعديل الرحلة (4s) → 15. M05 (3s) → 16. W04 الخط الزمني الكامل (5s) → 17. W01 ختام (4s).
  - يبدأ دائمًا بـReset تلقائي. مؤشر محاكاة (دائرة نابضة) يبرز العنصر قبل تنفيذ الفعل، تُعطَّل في `?captions=0&cursor=0` إن رغب المونتير.
  - التحكم: Space تشغيل/إيقاف، الأسهم خطوة سابقة/تالية، Esc خروج؛ شريط تقدم رفيع يختفي في وضع العرض. رابط مباشر `?story=1&present=1`.
  - التعليقات (captions) اختيارية أسفل الإطار، افتراضيًا مفعلة في Story Mode فقط.

## إطار الهاتف
- مكوّن `PhoneFrame` بإطار CSS/SVG واقعي (حواف معدنية داكنة، Dynamic Island، شريط حالة 9:41 مع إشارات وبطارية، مؤشر Home) يحيط بشاشة 390×844 دون حجب المحتوى.

## التحقق ومعايير القبول
- الشاشات الـ18 متاحة بالاسم والرابط المباشر، في الإطارين Device وClean.
- ترابط الأرقام والأوقات والعلامات والفواتير بين الويب والموبايل، قبل وبعد كل حالة وبعد Reset.
- Story Mode يكتمل من البداية للنهاية دون أخطاء، ويمكن إيقافه واستئنافه، ويُعاد تشغيله بنتيجة مطابقة.
- العمليات المؤكدة لا تتكرر؛ النتائج غير المنشورة محجوبة.
- لا قطع نصوص أو تزاحم في الإطارات المستهدفة؛ الشعار سليم؛ وضع العرض خالٍ من أدوات المعرض؛ الصور معالجة لونيًا مع بديل عند الفشل.
- تشغيل `pnpm build` بعد التنفيذ، و`pnpm format` على الملفات المعدلة. لا خادم تطوير إضافي، ولا ادعاء تحقق بصري لم يُجرَ.
